# 桌面任务 Agent

一个跑在 QQ 里的 Windows 桌面 Agent：用户在手机发消息，电脑上执行任务——打开网页、读写文件、操作窗口。

手写 ReAct 循环，不依赖 LangChain / LangGraph 等框架。任务与每一步的状态都落 SQLite，支持运行中取消、崩溃后对账、跨轮次记忆与上下文分层压缩。

## 核心能力

| 能力 | 实现 |
|---|---|
| **执行循环** | 手写 ReAct：模型返回 `tool_calls` → 执行 → 结果作为 Observation 回灌 → 直到不再调工具或触达预算上限 |
| **工具层** | 28 个桌面工具 + 1 个任务原文回查工具；统一 Schema、权限白名单、参数类型校验 |
| **浏览器操作** | **Windows UIA 直接操作真实窗口**，不走 CDP，可复用用户已登录的日常浏览器 |
| **任务状态机** | 任务 8 态、步骤 6 态、回复投递 5 态；三件事分开记，便于归因 |
| **落库粒度** | 每个工具**派发前写 PENDING → 转 EXECUTING → 执行完写结果**；工具消息则按批 append，避免孤儿 `tool_call` |
| **取消** | `asyncio.Event` 协作式取消；在模型请求前后与工具派发前双重检查；取消命令在用户锁外处理，避免被运行中任务阻塞 |
| **崩溃对账** | 启动扫描遗留任务标 `INTERRUPTED`，统计停在 `EXECUTING` 的风险步骤；`--check` 走 dry-run |
| **长期记忆** | `sessions.pinned` 存结构化偏好（目录、浏览器），不参与会话裁剪；用户改口是覆盖不是追加 |
| **历史任务召回** | 字符 bigram + idf 检索；**只在用户提到"上次/之前/一样/再做"时才触发** |
| **上下文压缩** | 按 token 预算分层降级：先压工具结果（保留头尾）→ 成组丢消息 → 目标降级（留 `task_id` 回查） |
| **会话裁剪** | 保存时按 token 预算裁（复用同一套压缩逻辑），轮数 30 仅作兜底 |
| **状态投影** | 上一个任务被中断时，从 `tasks` 表映射出"做到哪、哪步结果未知"，任务开始时注入一次 |
| **预算提示** | 每轮告诉模型"剩余时间、步数上限、该不该收尾"，只补 messages 给不了的信息 |

## 关键取舍

**1. 为什么用 UIA 而不是 CDP**

CDP 只能控制自己启动的浏览器实例，拿不到用户的登录态。UIA 控制真实窗口，能复用日常浏览器——代价是慢（秒级）、依赖窗口控件结构，页面改版会失效。

**2. 为什么状态要实时落、消息却批量落**

崩溃后能对账的只有状态：如果执行完才落库，进程在第 3 步死掉，库里就没有"我开过第 3 步"的痕迹。而工具消息必须成批 append，否则 `assistant.tool_calls` 和 `tool` 消息的 id 配对会被打断，模型会以为工具没执行、然后重试或编造结果。

**3. 为什么崩溃后只标记、不自动重跑**

实时落库能告诉我"第 3 步在跑"，但告诉不了我"那一步的消息发出去没有"。重跑可能让已经生效的外部动作再做一次。所以恢复只能做到"发现 + 标记 + 交给人"，这不是技术没做到，是副作用不可回滚决定的。

**4. 为什么不用 LangGraph**

确定性工作流适合图：节点可枚举、重放安全。桌面任务的路径依赖运行时网页状态，列不出来；而且我的恢复边界是"不重放"，与框架默认的 checkpoint 续跑语义冲突。**判断标准：能不能提前列出所有节点——能就上图，不能就别上。**

## 测试

```powershell
python -m unittest discover -s tests -v
```

81 个单元测试，覆盖：

- 上下文压缩（21）：预算分层、成组丢弃、孤儿调用防护、目标降级
- 会话裁剪（8）：token 优先、轮数兜底、系统提示与最新请求保留
- 长期记忆（13）：规则抽取、改口覆盖、按需召回、反例（"这次放桌面"不记）
- 中断检测（9）：遗留任务识别、dry-run 无副作用
- 预算提示（9）：只投 messages 给不了的信息
- 状态投影（11）：只认 `INTERRUPTED`、24 小时窗口、结果未知步骤警告
- 场景回归（6）与基础回归（4）：单工具、多步串联、工具失败、参数修正、取消、多用户并发

## 快速开始

```powershell
pip install -r requirements.txt
Copy-Item .env.example .env      # 填入模型接口
python main.py --check           # 不调用模型、不执行工具
python main.py --mode api        # 本机 /chat 与 /health
python main.py --mode qq         # 配置 QQ 凭据后启用
```

`--check` 只做静态启动检查。API 默认仅监听本机，**没有对外认证，不要暴露到公网**。

## 已知边界

- **不做自动恢复**：只发现并标记，重试需要"对账 + 工具幂等声明"两个前提，都还没做
- **文件层没有沙箱**：定位是单机单人部署；多用户共用一台机器时，用户能通过绝对路径访问彼此文件
- **危险操作没有审批流程**：`WAITING_CONFIRMATION` 状态已定义，但确认链路未实现
- **会话裁剪是有损的**：被裁掉的对话原文直接覆盖，没有归档
- **记忆范围窄**：只记两类结构化字段，抽不出自由文本约束
- **工具依赖真实环境**：28 个工具的实际执行需要 Windows 与各自软件，测试只覆盖无副作用路径
